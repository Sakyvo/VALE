## What to build

把剩余约 2151 个投稿包按目标仓库分批入库，目录规模从约 1150 增至约 3900。

归档继续存放于 GitHub 材质包仓库，沿用满仓标记与自动滚动机制——不迁到对象存储。当前编号最大的仓库尚有约 2.76GB 余量，其后约需新建 11 个仓库。每批填满一个仓库（约 5GB、约 200 个包），走完整的四阶段审批，每阶段需要与审阅结果绑定的摘要。分批的意义是把失败的重跑范围限制在一个仓库，而不是 53GB。

三个包超过 GitHub 的 100MB 单文件硬限。规范化的冗余与死路径清理在尺寸闸门之前执行，因此先跑规范化再判定尺寸——本来能救的包不该被误杀。清理后仍超限的记为待处理并保留审计原因，**不为它们新开存储通道**：那需要一次显式的存储路径扩展，是独立议题。

每批完成后跑九张真图的轻量回归。全部完成后跑一次完整重生成、完整回归、合成语料全量评估与规模化性能测量——这是本批工作的最终验收，也是判断两级检索在真实四倍规模下是否达标的唯一依据。

若最终评估显示搜图性能或召回不达标，如实记录并作为独立议题处理，不要在本 issue 内临时调参把测试压绿。
